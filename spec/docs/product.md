# Описание продукта RAG-manual-searcher

## Назначение

RAG-manual-searcher помогает находить объяснения в учебных пособиях и вузовских
конспектах по математике. Вместо ручного просмотра набора PDF пользователь задаёт
короткий вопрос на русском языке и получает ответ, сформированный с использованием
найденных фрагментов материалов.

Ценность продукта — сократить время поиска определения или объяснения в учебном
корпусе и помочь вернуться к ранее заданным вопросам через историю чатов.
Ответ модели служит вспомогательным материалом для учёбы: его следует сверять
с исходным конспектом.

## Аудитория и роли

Основная аудитория — студенты, которые готовятся к занятиям и экзаменам
и ищут информацию в доступных учебных материалах.

| Роль | Задачи и возможности |
| --- | --- |
| Посетитель | Зарегистрироваться и войти в аккаунт |
| Пользователь | Задавать вопросы, просматривать свои чаты и историю, удалять свои чаты, смотреть список книг |
| Администратор | Просматривать пользователей, менять их роли, блокировать и разблокировать доступ |

Регистрация создаёт обычного пользователя. Подготовка корпуса выполняется
разработчиком или оператором через скрипты; пользовательского API загрузки книг
в текущих маршрутах нет.

## Пользовательские сценарии

### Первый вопрос

1. Пользователь регистрируется с именем и паролем и входит в аккаунт.
2. При необходимости просматривает список доступных книг, чтобы понять состав корпуса.
3. Задаёт вопрос, например: «Что такое линейная независимость векторов?».
4. Сервис ищет фрагменты учебных материалов и передаёт вопрос с контекстом внешней модели.
5. При успешном ответе пользователь получает текст ответа, название модели и идентификатор чата.
   Вопрос и ответ сохраняются в истории, а название нового чата формируется из первого вопроса.

В запросе к модели задано требование отвечать на русском языке по найденному
контексту и ссылаться на фрагменты.
Если ответа в контексте нет, модели предписано вернуть
«Недостаточно данных в конспекте».

### Возвращение к вопросам

1. Пользователь открывает список своих чатов, упорядоченный по времени изменения.
2. Выбирает чат и просматривает историю вопросов и ответов с названием модели и временем диалога.
3. Отправляет новый вопрос с идентификатором выбранного чата или удаляет чат.

История объединяет записи для просмотра. При генерации нового ответа предыдущие
сообщения не передаются модели: каждый вопрос должен содержать достаточно
информации для самостоятельного поиска.

### Управление доступом

Администратор находит пользователя в списке, меняет его роль либо блокирует
или разблокирует доступ. Заблокированный пользователь получает отказ
при обращении к защищённым пользовательским операциям.

## Текущий объём реализации

В коде определены API регистрации и сессий, книг, чатов, истории и
администрирования. Доступ к пользовательским операциям требует авторизации;
чаты и история выбираются с учётом владельца.
Пользовательские сценарии сейчас описаны для API и могут быть проверены
через Swagger UI.

Поисковый конвейер предполагает BM25 и передачу трёх найденных фрагментов
внешнему LLM API. При ошибке модели обработчик пробует следующую модель
из настроенного в коде списка.

## Ограничения

- Вопрос содержит от 1 до 100 символов; длинные задания нужно сокращать.
- Для отправки вопросов и получения истории заданы лимиты 5 запросов в минуту
  и 100 в день. В текущем коде ключ ограничения.
- В подготовке PDF используются извлечение текста, очистка и нормализация слов.
- Качество ответа зависит от найденного контекста и модели.
- Внешнему провайдеру модели передаются вопрос и найденные фрагменты материалов
