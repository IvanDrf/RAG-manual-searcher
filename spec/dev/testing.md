# Проверка backend

## Полный прогон одной командой

Из корня репозитория:

```bash
make run-test
```

Нужны `make`, `uv` и работающий Docker с Compose v2. Команда устанавливает зависимости
из `back/uv.lock`, включая dev-группу, поднимает `docker-compose.test.yml`, ожидает
готовности сервисов и запускает все unit- и интеграционные тесты. Затем она останавливает
и удаляет тестовые контейнеры, включая случаи ошибки тестов, ошибки запуска Compose
и прерывания обычным сигналом. Ненулевой код завершения блокирует коммит и проваливает CI.
Локальный `.env` для тестов создавать не требуется.

В `.pre-commit-config.yaml` эта команда подключена как локальный хук `backend-tests`,
который запускается один раз при каждом коммите независимо от списка изменённых файлов.
Чтобы включить хуки в своём checkout, выполните из корня:

```bash
uv run --project back pre-commit install
```

Запустить только тестовый хук вручную:

```bash
uv run --project back pre-commit run backend-tests --all-files
```

GitHub Actions запускает ту же команду при push и pull request; отдельно проверяет
Ruff lint и форматирование. Шаг очистки с `if: always()` дополнительно останавливает
тестовые сервисы при ошибке или отмене задания.

## Отдельные проверки

Команды Python выполняются из `back/`. Используется окружение проекта, глобальная установка пакетов не нужна:

```bash
uv sync --locked --dev
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

## Unit-тесты

По умолчанию pytest запускает только быстрые тесты, исключая маркер `integration`.
В `tests/conftest.py` до импорта приложения задаются тестовые параметры конфигурации,
поэтому тесты не зависят от секретов и адресов из локального `.env`.

- `pytest-asyncio` запускает асинхронные тесты и фикстуры с отдельным event loop на тест.
- Hypothesis проверяет свойства JWT, паролей, схем запросов и ограничений имени чата.
- [fakeredis](https://fakeredis.readthedocs.io/) заменяет Redis в памяти, включая async API,
  байтовые/строковые ответы, TTL и ошибки подключения.
- `unittest.mock` с `AsyncSession` spec заменяет границу SQLAlchemy. Проверяются параметры SQL,
  фильтры владельца, порядок, пагинация, блокировки, операции записи и закрытие потокового результата.
  Эти моки не исполняют SQL и не эмулируют PostgreSQL: реальное поведение проверяется отдельно.
- `httpx.MockTransport` подставляет ответы LLM без внешних запросов; фоновые задачи статистики
  дожидаются завершения. HTTP-тесты авторизации используют ASGI transport и лимитер в памяти.
- В `tests/unit/` запрещено открывать сетевые соединения. Обращение к настоящему сервису приводит к ошибке теста.

Запуск выбранной части:

```bash
uv run pytest tests/unit/test_postgresql_repositories.py -v
uv run pytest tests/unit/test_auth_http.py -v
```

Unit-тесты проверяют веса BM25 и формирование RAG-промпта. Найденные чанки
подставляются без обращения к PostgreSQL.
Unit-тесты не скачивают NLTK-ресурсы, модели или корпус и не вызывают платный LLM API.

## Интеграционные тесты

Для проверки SQL, pgvector и реального Redis предусмотрен отдельный Compose. Он также
поднимает ClickHouse для проверки подключения; сериализация записей аналитики проверяется unit-тестами.
Рабочие контейнеры и тома не используются. Тестовые адреса фиксированы на loopback:
PostgreSQL — `25432`, Redis — `26379`, ClickHouse HTTP — `28123`.

Из корня репозитория:

```bash
docker compose -f infrastructure/back/docker-compose.test.yml up -d --wait
```

Из `back/`:

```bash
uv run pytest -m integration tests/integration -v
```

PostgreSQL-фикстура создаёт расширение vector и ORM-таблицы внутри транзакции,
которая откатывается после каждого теста, включая вызовы `session.commit()`.
Тесты BM25 используют ту же PostgreSQL-фикстуру и запускаются без дополнительных
переменных окружения. Проверяются ранжирование, повторное построение индекса,
изоляция временных таблиц и восстановление исходных текстов старых чанков.
Нормализация входных фрагментов в этих тестах подменена, поэтому NLTK-ресурсы не нужны.
Интеграционные тесты не проверяют применение Alembic-миграций и не запускают настоящий LLM.
Данные PostgreSQL и ClickHouse хранятся в tmpfs и удаляются вместе с тестовыми контейнерами.
Redis работает без сохранения на диск; его тест удаляет только собственный случайный ключ.

После проверки остановите тестовое окружение из корня:

```bash
docker compose -f infrastructure/back/docker-compose.test.yml down
```

Если Docker или необходимые образы недоступны, unit-тесты остаются независимыми от них.
Интеграционные тесты при явном запуске должны завершиться ошибкой подключения, а не
пропускаться с ложным сообщением об успешной проверке.
