# MathContext · React

Русскоязычный интерфейс для чата, библиотеки математических лекций и панели администратора.

## Локальный запуск

1. Запустите backend с работающей авторизацией из ветки `dev/pg_vector` или укажите адрес уже запущенного backend. Для локального backend используйте инструкции его README, включая настройку `.env`, PostgreSQL, Redis и миграций.
2. Из папки `front/` установите зависимости и запустите Vite.

```bash
cd front
npm ci
npm run dev
```

Откройте URL, который напечатает Vite. По умолчанию запросы `/api/v1` (авторизация и чат)
проксируются в `http://127.0.0.1:8080`. Для другого адреса создайте
`front/.env.local` и перезапустите Vite.

```dotenv
AUTH_API_TARGET=http://127.0.0.1:8080
```

Для dev-режима открывайте frontend через loopback-адрес. При развёртывании
обслуживайте frontend через HTTPS и проксируйте `/api/v1` на том же
origin, чтобы браузер мог отправлять защищённые cookies сессии.

## Сценарии

- Войти существующим аккаунтом или зарегистрировать обычного пользователя. Роль приходит от API. Для панели администратора нужен аккаунт с серверной ролью `admin`.
- Создать чат и отправлять вопросы backend через `POST /api/v1/chat/promt`. Полученный `chat_id` используется для следующих сообщений в этой переписке. Ответы и вопросы сохраняются backend, а список отображённых переписок кэшируется в этом браузере отдельно для каждого аккаунта.
- Фото отключены: текущий chat API принимает только текст и не поддерживает анализ изображений.
- Открыть каталог, выбрать предмет и PDF, выделить текст на странице и нажать **«Обсудить в чате»**. Цитата передаётся внутри текста вопроса; общая длина вместе с названием источника и вопросом ограничена 100 символами текущего API. Страницы без текстового слоя доступны для чтения.
- Под администратором открыть сводку расхода токенов. График и таблица используют демонстрационные данные.

Чат отображает только ответы backend. Во время HTTP-запроса показано ожидание;
после ответа отображается его текст без искусственной паузы размышления.
При ошибке показывается сообщение, вопрос возвращается в поле ввода. POST-запросы
автоматически не повторяются. Перед отправкой проверяется сессия и при необходимости
обновляются cookies авторизации. Если аккаунт в другом окне изменился, отправка блокируется.

Старые демо-переписки не показываются как реальные и остаются в прежнем localStorage.
Новый кэш находится в ключе `mathdesk.backend-chats.<user_id>`; серверные чаты и история
при загрузке страницы пока не скачиваются. Поэтому очистка localStorage скрывает
переписки в текущем интерфейсе, но не удаляет их из PostgreSQL.
Административная статистика по-прежнему демонстрационная.

После изменения `vite.config.ts` перезапустите Vite. Для опубликованной статической
сборки нужен отдельный reverse proxy `/api/v1` к backend: настройки Vite dev/preview
не добавляют маршрутизацию в статический хостинг.

Команда `npm run build` проверяет TypeScript и собирает приложение с библиотекой PDF в `front/dist/`.

Проверка API-клиента без сети и LLM:

```bash
npm test
```

Тесты используют встроенный Node test runner и установленный TypeScript;
дополнительных тестовых зависимостей нет.
